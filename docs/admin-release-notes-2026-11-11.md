# Admin UX/API release notes — web 0.1.36, backend 1.0.30

**Дата:** 2026-11-11. **Версии:** backend `1.0.30`, web `0.1.36`.
**База:** `60cc9a0`. **Статус:** проверено автотестами; на сервере
пользователя изменения ещё не развёрнуты.

## Что изменилось

- **Авточистка оригиналов управляется из админки.** Вместо бейджа —
  `Switch` с подсказкой «Удаляет наименее просматриваемые оригиналы при
  нехватке места». Значение применяется к очереди сразу и сохраняется
  в таблицу `settings` (ключ `storage.auto_cleanup_originals`), поэтому
  переживает рестарт; `storage.auto_cleanup_originals` из YAML остаётся
  fallback'ом, если сохранённой настройки нет или её не удалось прочитать.
- **Карточки хранилища показывают занятое разделом.** Для каждого
  каталога отдаётся `used_bytes` (размер этого каталога), в UI —
  «Раздел занимает X», «Свободно на диске Y (Z%)» и «Всего T». Каждый уникальный
  каталог обходится один раз, размер переиспользуется в секциях
  видео/аудио/оригиналов/временных.
- **Пояснение к таблице пользователей.** Добавлена подсказка: новые
  пользователи появляются после первого входа по email; себя нельзя
  удалить или снять администратора. Создание пользователей не
  добавлялось осознанно (OTP создаёт запись при входе), управление
  другими пользователями не менялось.

## API

- `GET /api/admin/storage` — добавлены `used_bytes` у каждого диска;
  `auto_cleanup` теперь берётся из очереди (persisted setting).
- `PUT /api/admin/storage/settings` с телом `{"auto_cleanup": bool}` —
  admin-only. Применяет флаг к очереди, сохраняет в БД; при ошибке
  записи откатывает флаг и отвечает 500. Возвращает
  `{"auto_cleanup": bool}`. Отсутствие ключа или неверный тип — 400.
