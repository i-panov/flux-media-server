# Ревью и текущее состояние Flux Media Server

**Дата:** 2026-11-09. **Статус:** завершено; P0/P1 закрыты, P2/P3 закрыты или
осознанно ограничены. Документ заменяет первоначальный длинный отчёт: перед
вами итоговое состояние, решения и журнал коммитов.

## 1. Итог

- **Backend** — рабочая основа: Fiber + GORM + SQLite (WAL), OTP/JWT,
  очереди upload/transcode/extract, сканер, корзина, версионированные
  ad-hoc миграции, trusted proxies, security headers.
- **Web** — основной клиент. Функционально почти равен legacy Flutter и
  обгоняет его админкой, мемами, ТВ-режимом и PWA.
- **Mobile** — ранний каркас: OTP-вход, SecureStore, health, списки
  видео/аудио, настройки, i18n. Плеера, деталей, коллекций, избранного и
  загрузки пока нет.
- **`packages/shared`** — платформенно-нейтральный TS: transport/auth,
  media/format, query, storage. Web и mobile используют его без копий схем.
- **Legacy `frontend/`** (Flutter) не развивается и оставлен только как
  справочник функций.

## 3. Состояние клиентов

### Web — основной клиент

Есть: OTP-сессия и refresh, видео/аудио/мемы, поиск и сортировка, детали,
нативный видеоплеер, аудио-плеер с очередью (shuffle/repeat/reorder,
текущий трек), lyrics/translation, избранное, артисты с обложками,
коллекции (CRUD, вложенность, перенос, bulk), загрузка, извлечение аудио,
правка метаданных/обложки, корзина, админка, ТВ-режим, PWA, ru/en.

Ограничения: нет offline/downloads (решение: web streaming-only), нет
скорости/PiP/пользовательского скачивания видео, нет отдельного ряда
«Recently Added», виртуализация списков частичная.

### Mobile — ранний каркас

Есть: OTP-вход и SecureStore, `AuthGate`, настройка URL сервера, home/health,
списки видео/аудио с серверной пагинацией, logout, i18n ru/en, тест i18n,
smoke-сборка.

Нет: деталей и плеера, очереди, lyrics, избранного, коллекций, загрузки,
правки метаданных, корзины, артистов, мемов, админки, offline, фонового
аудио.

Оценка относительно Flutter: web ~85–90% функций, mobile ~10–15%
(уровень «вход + списки»).

## 4. Находки и решения

### Backend

| ID | Итог |
|---|---|
| B-01 | Extractor не удаляет существующий `dstPath` при ошибке ffmpeg; тест. |
| B-02 | Сканер отправляет пропавшие файлы в `AutoTrashed`-корзину, live-first поиск, purge защищён. |
| B-03 | Patch-семантика метаданных: `""`/`0` очищают, пустой `Metadata` не создаётся. |
| B-04 | Docker: 8080 внутри, 8095 на хосте, healthcheck совпадает. |
| B-05 | Превью/обложки: temp-файл + atomic rename, старые не портятся. |
| B-06 | Transcode не удаляет единственную копию при Direct/Remux; purge-failure → soft-delete. |
| B-07 | Restore проверяет `IsPathAllowed`, файл и не-каталог (409/500). |
| B-08 | `server.trusted_proxies`; XFF только от доверенного peer, без X-Real-IP. |
| B-09 | Permissions-Policy; HSTS только на HTTPS/X-Forwarded-Proto. |
| B-10 | CI Go 1.25, Alpine 3.22. |
| B-11 | Legacy JWT без type-claim удалён. |
| B-12 | Ошибки БД в `/subs` → 500, не 404. |
| B-13 | Мёртвые `POST/PUT /api/media` удалены. |
| B-14 | Каталоги создаются до воркеров; backfill в WaitGroup и отменяется в Shutdown. |
| B-15 | `schema_migrations` версии 1, повторный прогон пропускается. |
| B-16 | `metadata/search` помечен экспериментальной заглушкой. |
| B-17 | `.mov` определяется по расширению и ремуксится в MP4; Direct — только MP4/M4V. |
| B-18 | `UploadCover` пишет во временный файл и заменяет atomic rename. |

## 5. Осознанные ограничения

- **Offline/downloads** — отдельный проект (Cache API/OPFS); web остаётся
  streaming-only. Mobile offline — после появления плеера.
- **Recently Added** — главный список уже отсортирован по новым; отдельный
  ряд дублировал бы его и ломал TV-focus-ключи.
- **Виртуализация** — серверная пагинация по 24 + `content-visibility`.
  Полная виртуализация конфликтует с TV spatial-навигацией, которой нужны
  смонтированные цели.
- **Видеоплеер web** — нативный `<video>` без speed/PiP и пользовательского
  download; это следующий продуктовый шаг, если нужен.
- **Mobile** — не заменяет Flutter, пока нет деталей/плеера/коллекций.
