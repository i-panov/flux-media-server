# Video Detail With Player — Design Spec

**Date:** 2026-08-17
**Status:** Approved

## Problem

The video flow currently requires two taps to start playback: tap a card on the Video tab → open `MediaDetailScreen` (cover + metadata + buttons) → tap "Play" → push a separate fullscreen `PlayerScreen` with the actual video. This is two screens and feels disconnected compared to modern players (YouTube, Apple TV, Netflix) where the video and its details are visible together on one screen.

## Goals

1. **Single screen for video details and playback** — `VideoDetailScreen` shows the video player at the top and the metadata/action buttons in a scrollable area below, on the same screen.
2. **Tap to enter fullscreen, tap again to return** — fullscreen is a state of the same screen, not a separate push. (YouTube-style.)
3. **Thumbnail as poster** — before playback starts and during loading, the player area shows the media thumbnail (existing `MediaImageKind.thumb`). This is standard behavior in all players.
4. **All existing actions available** — favorite, add to collection, download, queue, edit metadata, change cover, delete. Same as the current detail screen.
5. **Unified player state** — playback continues across navigation; `PlaybackCoordinator` is the single source of truth and is not duplicated.

## Non-Goals

- Audio tab changes. The audio flow (mini-player + lyrics/translation screen) is unchanged. `MediaDetailScreen` is no longer used for audio either (see Compatibility section).
- Backend API changes.
- New player features (cast, picture-in-picture, etc.).
- Resuming the `AudioPlayerScreen` (lyrics/translation/queue) — that screen remains for audio only.

## Architecture

### Files

**New:**
- `frontend/lib/features/video/presentation/screens/video_detail_screen.dart` — root screen, replaces `media_detail_screen.dart`.
- `frontend/lib/features/video/presentation/widgets/video_player_panel.dart` — the player + controls, in embedded and fullscreen states.
- `frontend/lib/features/video/presentation/widgets/video_details_panel.dart` — metadata and action buttons, extracted from the current `MediaDetailScreen.loaded` body.

**Deleted:**
- `frontend/lib/features/player/presentation/screens/player_screen.dart` — the separate fullscreen player. Its logic moves into `VideoPlayerPanel`.

**Modified:**
- `frontend/lib/core/router/app_router.dart` and `app_router.gr.dart` — remove `PlayerRoute`; rename `MediaDetailRoute` to `VideoDetailRoute` (regenerated by `build_runner`).
- `frontend/lib/features/video/presentation/screens/video_screen.dart` — references to `MediaDetailRoute` updated to `VideoDetailRoute`.
- `frontend/lib/features/collections/presentation/screens/collection_detail_screen.dart` — same rename for video items. Audio path unchanged.

### `VideoPlayerPanel` (new widget)

- `ConsumerStatefulWidget` with `Media media`, `bool isFullscreen`, `VoidCallback? onToggleFullscreen`.
- Uses the existing `videoControllerProvider` and `PlaybackCoordinator` exactly as the current `PlayerScreen` does.
- Layouts:
  - **Embedded**: rendered at the top of `VideoDetailScreen`'s `Column`. `AspectRatio` is derived from the current video size when known; before that, `16/9`. Black background. `MaterialVideoControls` overlay (theme from `_buildMobileControlsTheme` in the deleted `PlayerScreen`, moved here).
  - **Fullscreen**: when `isFullscreen == true`, the panel renders as `Positioned.fill` over a black background. `SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)` and all four orientations (matching the current `PlayerScreen`).
- **Poster**: while the player is in `PlaybackInitial` / `PlaybackLoading` / `PlaybackError`, show `AuthNetworkImage` with `MediaImageKind.thumb` (existing helper) as the panel's content. When `PlaybackPlaying` arrives, the player surface takes over.
- Controls: top bar (back button, which in fullscreen is "collapse fullscreen" instead of "back") and bottom bar (±10s, speed, position indicator, fullscreen toggle) — migrated verbatim from the current `PlayerScreen._buildPlaying` `mobileTheme`.
- Resume overlay and lifecycle (`WidgetsBindingObserver`, pause on background) are preserved.

### `VideoDetailsPanel` (new widget)

- `ConsumerWidget` with the same data and callbacks the current `MediaDetailScreen` uses: `media`, `onChangeCover`, `onEditMetadata`, `onDelete`, `onToggleFavorite`, `onAddToCollection`, `onDownload`, `onAddToQueue`.
- Visual contents: title, year, type, artists, album, genre chip, description, duration, then buttons (Play, Favorite, Collection, Download, Add to Queue). The Play button now triggers `PlaybackCoordinator.play(media)` directly instead of pushing a route.
- `changeMediaCover`, `deleteMediaWithConfirm`, `showEditMetadataDialog` continue to be called from here.
- The "Play" button is removed from `VideoDetailsPanel` because playback is the primary action of `VideoPlayerPanel` (which can also be tapped to start). If the player is in `initial/loading/error` and a user wants a more obvious start, the thumbnail itself is tappable (or a play overlay button on the thumbnail).

### `VideoDetailScreen` (new root)

- `ConsumerStatefulWidget` with `mediaId`.
- Owns local state `bool _isFullscreen = false` and forwards toggle to `VideoPlayerPanel`.
- Watches `mediaDetailProvider(mediaId)`; renders loading/error as today.
- Loaded layout (embedded state):
  ```
  Scaffold(
    appBar: AppBar(...) // optional; back button
    body: Column(
      children: [
        VideoPlayerPanel(media: media, isFullscreen: false, onToggleFullscreen: ...),
        Expanded(
          child: SingleChildScrollView(
            child: VideoDetailsPanel(media: media, ...callbacks),
          ),
        ),
      ],
    ),
  )
  ```
- Loaded layout (fullscreen state): `Scaffold` body becomes a `Stack` with `VideoPlayerPanel(isFullscreen: true)` covering the full screen. The AppBar and details are hidden; the panel's own back button collapses fullscreen.
- AppBar (embedded) keeps the three actions: change cover, edit metadata, delete — moved from the current `MediaDetailScreen` AppBar.

### Router changes

- `PlayerRoute` removed; `PlayerRoute` line in `app_router.dart` deleted. `app_router.gr.dart` regenerated.
- `MediaDetailRoute` renamed to `VideoDetailRoute` (more accurate name now that it's video-only). Page class renamed to `VideoDetailScreen`. References in `video_screen.dart` and `collection_detail_screen.dart` updated. `app_router.gr.dart` regenerated.
- `AudioPlayerRoute` and `AudioPlayerScreen` untouched.

## Compatibility

`MediaDetailScreen` was previously used for both video and audio. In the current codebase, however, no callsite pushes `MediaDetailRoute` for audio tracks (verified by search: `MediaDetailRoute` is only used from `VideoScreen` and `CollectionDetailScreen`'s video branch). For collections, audio items go straight to `AudioPlayerRoute`; only video items reach `MediaDetailRoute`. After this change, audio tracks have no detail screen — the existing `AudioScreen` track rows with their action buttons (favorite, download, queue, collection, edit, change cover, delete) already cover that use case. No audio UX regression.

## Testing

- New: `test/features/video/video_player_panel_test.dart` — verifies that:
  - Tapping the panel toggles `onToggleFullscreen`.
  - In `initial` state, the thumbnail is shown.
  - When the panel is fullscreen, the layout expands to fill.
- New: `test/features/video/video_details_panel_test.dart` — verifies the play callback wires to `PlaybackCoordinator.play(media)`.
- Existing tests for `media_detail_screen` are removed (the class is deleted). They don't test unique behavior worth preserving.
- `flutter analyze` and `flutter test` must pass.

## Risks

- **`PlayerScreen` removal**: callers that still import `PlayerScreen` will fail compilation. The only callers are `app_router.dart` and `app_router.gr.dart` (route registration) and `media_detail_screen.dart` (push call inside the Play button). All three are updated.
- **Layout regressions**: the embedded panel is a fixed `AspectRatio` at the top, not a flexible area. On small phones in landscape, the details area below might be cramped. Acceptable trade-off — landscape is rare on phones, and fullscreen is one tap away.
- **No auto-play on screen open**: when the user opens a video, playback does not start automatically (matches current `MediaDetailScreen` behavior). Tap on the player area or the play overlay on the thumbnail to start.
